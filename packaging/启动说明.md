# hoshino 星野 · 部署包说明

这一份是 Next.js 的 standalone 产物：目标机**不需要 npm install，也不需要源码**，有 Node.js 就能跑。

## 服务器需要什么

只有一项硬性要求：**Node.js 20.9 以上**（Next 16 的 `engines` 下限，建议直接上 22 LTS）。

除此之外什么都不用装：

| 需要 | 不需要 |
| --- | --- |
| Node 20.9+（`node -v` 确认） | npm install、pnpm、yarn |
| 一个可监听端口 | 构建工具、Python、make、g++ |
| 反代 + TLS（Nginx / Caddy） | git、源码、`node_modules` 重装 |
| 约 20MB 磁盘（解压后） | 数据库、Redis、对象存储 |
| 约 100MB 内存（实测常驻 107MB） | 服务器出网（不调任何外部接口） |

包里**没有任何原生二进制**（`.node` / `.wasm` / `.so` / `.dylib` 数量为 0，`pack.sh` 会检查并打印），所以是纯 JS：Linux x64、ARM（树莓派 / 鲲鹏）、Alpine 的 musl、Windows 都能跑，不存在“在 macOS 上打的包在 Linux 上跑不动”的问题。Next 的 SWC 只在构建期用，运行期不需要；sharp 也剥掉了，因为本站没用 `next/image`。

内存是实测值：空载 + 处理一次首页请求后 RSS 约 107MB（堆用 27MB），1GB 内存的小机器完全够跑，不需要额外配 swap。

版本建议别用 Node 18 及更早（Next 16 直接拒绝启动）。国内机器装 Node 可以用 `https://npmmirror.com/mirrors/node/` 下二进制包解压即用。

另外两件与站点内容有关：

- 域名要能访问到服务器，国内还要求已完成 ICP 备案（页脚已按要求悬挂 `鲁ICP备2026052204号` 并链接工信部）。
- 时区建议给进程设 `TZ=Asia/Shanghai`。页面上的年龄是按服务器本地时间算的，UTC 机器在生日前后几小时内会差一天。systemd 单元里加一行 `Environment=TZ=Asia/Shanghai` 即可。
- 首屏与作品区的图片目前指向 `picsum.photos`（占位图）。服务器不需要出网，但**访客浏览器**需要能访问它，国内不稳。换成自己的图片：把文件放进 `public/`，改 `lib/site-data.ts` 里的地址后重新构建。

## 最快跑起来

```bash
tar xzf hoshino-blog.tar.gz
cd hoshino-blog
node doctor.mjs        # 自检：确认入口配置能被服务端接受
node start.mjs         # 启动
# 浏览器打开 http://127.0.0.1:3000
```

包内已经带了一份 `.env`（只含本站用到的两个变量），`start.mjs` 会把它读进进程再拉起服务，所以开箱可用，包括口令门。

**注意：不要直接 `node server.js`。** Next 的 standalone 入口不会自己读 `.env`（那是 `next start` 的行为），那样启动会拿不到口令配置，首屏一个按钮都不渲染，接口一律返回 503。`start.mjs` 就是补这一层的。

换端口 / 换绑定地址（真实环境变量优先，不会被 `.env` 覆盖）：

```bash
PORT=8080 node start.mjs
BIND_HOST=0.0.0.0 ./start.sh        # 需要直接对外监听时
```

`./start.sh` 是同一件事的包装：默认 `PORT=3111`、只监听 `127.0.0.1`，公网访问交给反代。

## 改口令与入口

先 `node doctor.mjs` 看当前配置解析成了什么（默认给地址打码，加 `--show` 看完整地址）。

编辑包内 `.env`：

```bash
HOSHINO_AGENT_PASSWORD=你的全局口令
HOSHINO_AGENT_TARGETS=[{"label":"agent 助手","href":"/agent"},{"label":"数据看板","href":"https://dash.hoshino.cloud","password":"这条自己的口令"}]
```

- 一个对象一个按钮，`label` 是按钮字样，`href` 是校验通过后跳转的地址（同站路径 `/agent` 或完整 `https://…`）。
- 条目里省略 `password` 就用全局口令。
- 首页是按请求渲染的，**改完 `.env` 重启进程就生效，不用重新构建**。
- 口令与地址只在服务端，不会出现在前端 JS 里；前端只拿到按钮字样和序号。
- 每个来源 IP 5 分钟内最多试 8 次，超出返回 429。反代后面记得把真实客户端 IP 传上来（见下面 Nginx 段），否则所有访客共用一个额度。

## 放到 systemd 上长期跑

```bash
sudo useradd -r -s /usr/sbin/nologin hoshino
sudo mkdir -p /opt/hoshino && sudo tar xzf hoshino-blog.tar.gz -C /opt/hoshino
sudo cp /opt/hoshino/hoshino-blog/deploy/hoshino-blog.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now hoshino-blog
journalctl -u hoshino-blog -f
```

单元文件里服务以 `127.0.0.1:3111` 监听，公网访问交给 Nginx / Caddy 反代。

## 反向参考配置

Nginx（关键是 `X-Forwarded-For`，限流按它认人）：

```nginx
server {
  listen 80;
  server_name hoshino.cloud www.hoshino.cloud;
  location / {
    proxy_pass http://127.0.0.1:3111;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Real-IP $remote_addr;
  }
}
```

Caddy 更省事，自动 HTTPS：

```
hoshino.cloud {
  reverse_proxy 127.0.0.1:3111
}
```

备案号要求主域名和 `www.` 都能访问，且两个域名的页脚都要有备案号。本页脚是组件级渲染，只要两个域名都反代到同一个服务就自动满足；如果 `www` 是独立入口，建议在 DNS/反代层把 `www` 301 到裸域。

## 包内容

```
start.mjs            该用这个启动：读 .env 再拉起服务
server.js            Next standalone 入口（不读 .env，别单独跑）
doctor.mjs           部署前自检，校验规则与服务端一致
env-file.mjs         .env 解析，start 与 doctor 共用
start.sh             前台启动脚本（默认 127.0.0.1:3111）
package.json         仅记录依赖，不需要再 npm install
node_modules/        已裁剪成运行必需的部分
.next/               构建产物（含 static 与字体文件）
.env                 本站环境变量（600 权限，含真实口令）
deploy/              systemd 单元示例
启动说明.md           本文件
```

`.env` 里只保留了本站用到的 `HOSHINO_AGENT_PASSWORD` 与 `HOSHINO_AGENT_TARGETS`。开发机上另有一份完整的 `.env`（含 DNSPod 凭据），那个文件 git 不跟踪，也没进这个包。

## 安全提醒

- 这份 `.env` 里有真实口令，入口地址里还带了 token，整个压缩包按机密对待：别上传到公开仓库、别发到群里、别放进网盘公开链接。传服务器用 `scp`，落地后 `chmod 600 .env`。
- `doctor.mjs --show` 会把完整地址打进终端，排查完记得清屏或别把这段贴给别人。
- 口令门是轻量遮挡，不是账号体系。里面那台 Agent 服务本身要另加认证（Nginx `auth_basic`、OAuth，或应用内登录）。
- 想撤掉某个入口，删掉 `.env` 里那条对象重启即可；一条都没配好时首屏不渲染按钮，接口返回 503。
